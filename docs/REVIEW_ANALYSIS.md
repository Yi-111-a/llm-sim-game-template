## 高赞差评中反复出现的具体症状（原话归纳）
1. 买断后还要买 token/代币，不能用自己的 API（BYOK）；核心流程（诏书、国策、存档、BYOK）走官方线上网关 → 断线、卡死、扣点不出内容。
2. 账目错乱：一次性支出被登记为"常规/杂项"持续支出，每回合重复扣款；AI 事后编理由凑数。
3. 状态不同步：被斩首的人下回合还活着能对话；提拔的官员不在大臣列表；地图显示叛军已灭/仍在；同一大臣在不同面板数据不互通。
4. 指令执行率低：千字诏令只"判定 20%"；任免、扩军、建厂后面板不变；交代的任务下回合不重复就失效（缺少"持续政令"）。
5. 项目/产量不可追踪：工厂永远"下季度完成"，库存问三次三个数，产量靠 AI 猜。
6. 地理/逻辑荒谬：人物瞬移（四川→皮岛→四川）；粮仓建在军队旁仍断粮（规则缺失）。
7. 强制历史模板/剧情杀：无视玩家已建立的科技/铁路优势，套用"松锦之战"全军覆没。
8. AI 记忆差、嘴硬、敷衍、瞎编；回答同质化。
9. 性能卡顿掉帧；内测修复的 bug 回退；开发者沟通差。

## 对应设计结论（新架构必须做到）
- 本地优先 + BYOK：任意 OpenAI 兼容端点（含本地 Ollama），无官方网关；用量与费用实时可见。
- 代码是唯一事实来源：LLM 只能"提议"类型化状态操作（StateOp），由确定性引擎校验后执行；叙事必须基于已执行的事实生成。
- 账本显式区分 one_off / recurring(有截止回合)，每回合结算可审计。
- 统一实体注册表：人物生死/职位/位置唯一存储，所有面板与对话读同一份；死者不能行动/对话（除非剧本允许"托梦"类）。
- 诏令执行回执：每条子句 → 操作 → 已执行/驳回(原因)/需澄清，执行率可见；支持"常设政令"每回合自动执行。
- 项目系统：建设/训练有明确工期、成本、产出，自动推进完成，库存为数值而非叙述。
- 移动/地理规则：人物与军队有位置，跨区移动需时间。
- 历史倾向是可调"引力"参数而不是硬模板；推演必须读取玩家已解锁的科技/设施。
- 事件溯源存档（JSONL 树，可回档/分支）；人物记忆 = 结构化事实 + 摘要压缩。

## 问题 → 新架构模块 对照

| 差评问题 | 新架构的解决方式 | 落地位置 |
|---|---|---|
| 付费/代币、不能 BYOK、依赖服务器 | 本地运行；支持任意 OpenAI 兼容端点（含 Ollama）；内置离线 mock；每次调用的用量和估算费用都可见 | `backend/simcore/llm/`、`/api/usage`、SettingsPanel |
| 数值/账目错乱 | 数值只由确定性引擎结算；账本显式区分 one_off 和 recurring(turns)，每回合逐行列出 | `domain/ops.py`、`domain/turn.py`、LedgerPanel |
| 状态不同步 | 单一 WorldState 实体注册表，所有面板、对话和提示词读同一份数据；死者不能任职、不能对话 | `domain/models.py`、`domain/rules.py` |
| 指令不执行/曲解 | 诏书执行回执：每个条款都标明 applied、rejected(原因)、delayed、needs_clarification；支持常设政令 | `agent/roles.py` edict_interpreter、ReceiptPanel |
| AI 瞎编/嘴硬 | 叙事只能基于 TurnReport 中的事实生成，不得出现事实里没有的数字 | `prompts/narrator*.md` |
| AI 记忆差 | 人物结构化记忆（remember op）+ chronicler 压缩摘要；会话是 JSONL 树 | `store/session.py` |
| 项目/产量不可追踪 | start_project 声明工期、每回合成本和完工效果，完工自动执行 | ProjectsPanel |
| 地理荒谬 | 用邻接关系和 travel_turns 计算移动时间，在途状态显式记录 | `regions.yaml` |
| 强制历史 | 历史事件设置前置条件和 gravity 概率，玩家改变了条件后事件就不会触发 | `events.yaml` |
| BUG/回退 | 种子随机数 + 回放校验 state_hash；pytest 覆盖账本、人事、项目、事件、回放；CI | `tests/`、`.github/workflows/ci.yml` |
